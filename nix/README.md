# Fixture recorder for metadata schema 6

`fixture-recorder.nix` builds a pinned historical `nargo` for applications whose
replay engine reads `meta.dat` schema 6. Import the function with the application's
pinned `pkgs`:

```nix
import "${noirSource}/nix/fixture-recorder.nix" { inherit pkgs; }
```

It pairs compiler `875ee4855112922d4526c5f3e97448386dfc76f6` and its locked Rust
trace format `1eae5894ce97001f4b013e50767cc2243a1ed47f` with Nim writer
`051efd22b00ec3b88676fb07755a65c5a4ca8fde`. Both sides of that FFI use the same
14 I/O kinds, from `Write = 0` to `EvmEvent = 13`. The current recorder uses a
different schema and I/O ABI, and retains its own dependency pins.

The backport adds two options to the historical CLI:

```sh
nargo trace --out-dir out \
  --recording-id 01949fcc-7d92-7e9c-8000-000000000001 \
  --recording-workdir /fixtures/example
```

The supplied identity must be a canonical UUIDv7. The logical working directory
only changes container metadata; source paths are normalized against the actual
working directory. Use both options for portable, byte-identical fixtures.
Omitting them preserves fresh recording identities and the actual working directory.
The compiler and writer emit the container directly; no generated bytes are patched.

The package's install check drives its real CLI from two different source
directories, compares entire containers, and proves identity and working-directory
options affect the output. It also checks fresh default identities and rejection
of invalid identities before any container is created. A consumer must additionally
open generated fixtures with its actual replay engine. The installed
`share/noir-fixture-recorder/provenance.json` records the source revisions, backport
digest and compiler versions; the Nix derivation records the complete toolchains.
