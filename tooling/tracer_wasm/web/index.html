Noir source → a .ct trace container, entirely in WebAssembly

The text in the box below is a JavaScript string. It is copied into the linear memory of a single wasm32-unknown-unknown module and compiled there — the Noir compiler, its standard library and the ACVM/Brillig interpreter are all inside the module — the module executes it, and hands back a complete .ct CodeTracer container, assembled in that same linear memory. There is no server doing any of this: the page is static files, and the module is instantiated with an empty import object, so it has no way to call out.

What the module produced

One thing this container does not carry: columns. It is written by the pure-Rust CtfsTraceWriter, the only .ct writer that builds for wasm32-unknown-unknown today. That writer has no column-bearing step encoder — no paths.dat Layout A line-length table, no sekDeltaColumn opcode — so it does not set the meta.dat capability bits either, because advertising a capability the bytes do not carry would make a reader ask for columns and decode garbage rather than fail. The Noir recorder does request column-aware steps on every trace, and the writer reports that the request was dropped; that is the column-aware row above. Native nargo trace, which uses the Nim writer, still produces the column-aware container.
