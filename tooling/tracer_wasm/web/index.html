Noir source → execution trace, entirely in WebAssembly

The text in the box below is a JavaScript string. It is copied into the linear memory of a single wasm32-unknown-unknown module and compiled there — the Noir compiler, its standard library and the ACVM/Brillig interpreter are all inside the module — and the module hands back the execution trace. There is no server doing any of this: the page is static files, and the module is instantiated with an empty import object, so it has no way to call out.

What the module produced

What this download is not, yet: a .ct CTFS container. The module returns the low-level event stream — the same events, in the same order, that the container writer would buffer — and the download is that stream as JSON. No .ct writer can currently be reached from wasm32-unknown-unknown: the Nim writer links a static library, and the pure-Rust one gates its CTFS writer behind #[cfg(not(target_arch = "wasm32"))] and pulls in C zstd. Making one reach wasm is being done separately; when it lands, this button hands you the container instead, and nothing else on this page changes.
